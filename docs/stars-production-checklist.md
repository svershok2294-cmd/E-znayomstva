# Stars release checklist

- Review the text in `payment-terms.js`. Before creating an invoice, the client displays this text and sends the accepted version. The server rejects missing or outdated versions and saves the accepted version on the order.
- Verify production bot `e_znayomstva_bot`, the exact Render API service and Firebase project `nazviazku`. Keep the sandbox on its separate Telegram test bot and Firebase project.
- For an owner-only pilot, set `STARS_PILOT_BUYER_ID` to the intended verified Telegram ID. Store a randomly generated 32–256 character webhook secret privately in Render as `TELEGRAM_STARS_WEBHOOK_SECRET`. The code gates real payments behind `ENABLE_TELEGRAM_STARS=true` and `ENABLE_LIVE_TELEGRAM_STARS=true`.
- `REGISTER_LIVE_STARS_WEBHOOK=true` asks the production server to register only its own webhook. Startup checks the Telegram bot username and refuses to replace an existing webhook with a different URL. Pin the deploy to the reviewed commit and verify the active commit. Use `/health` to confirm `starsWebhookReady: true` before publishing the payment client.
- From the intended bot, verify `/terms` and `/paysupport`. The owner handles disputes through the published support contact. Find the verified charge in `ez_vip_charges` or `ez_gift_charges`, verify the buyer and payment with the receipt, and use Telegram's `refundStarPayment` method for an approved refund. Confirm the refund event and the matching status in Firestore. Never share the bot token or webhook secret.
- Verify checkout cancellation, a completed VIP purchase, a gift delivered to a consenting recipient, and a refund. Simulated tests do not prove that the deployed Telegram webhook reaches Render. Keep purchases limited to the pilot account until these checks are complete.
- To pause new purchases while still accepting payment and refund events, restrict access to the payment pilot or remove the payment buttons. Keep the webhook and its secret available for existing orders.
